# wit.et

The source of [ainsleewang.github.io](https://ainsleewang.github.io): a
personal site set as a small paper magazine. Interface text is Traditional
Chinese; posts are Markdown; there is almost no client JavaScript. Built with
[Astro](https://astro.build) as a static site.

## Layout

```
src/
  content/posts/     posts, one Markdown file (or folder) each
  pages/             routes: home, posts, tags, about, archive, 404, rss
  layouts/           Base (head, SEO tags, header, footer), ArticleLayout (reading page)
  components/        header, footer, lists, reading head, small Latin/Chinese helpers
  lib/               post helpers, tag names (labels.ts), Markdown plugins
  styles/            global.css, site-scale.css (every font size), article.css, list.css
                     vendor/tokens.css is generated by scripts/sync-tokens.sh; do not edit
public/              favicon, touch icon, manifest, robots.txt; og/ is generated
scripts/             verify.sh and its checks, og.mjs (share cards), icons.mjs
docs/                specs, author guide, notes for each change (docs/pr/)
.github/workflows/   deploy.yml (Pages) and ci.yml (pull requests)
```

## Writing a post

Add a Markdown file to `src/content/posts/`. Frontmatter fields and the
supported Markdown parts are in [`docs/WRITING.md`](docs/WRITING.md).

## Local development

Node version: see `.nvmrc`.

```sh
npm ci
npm run dev        # http://localhost:4321, sample posts included
npm run build      # share cards (prebuild), then the site into dist/
npm run preview    # serve dist/
```

`scripts/verify.sh` is the one-command check: type check, build, colour grep,
link check, screenshots at three widths, type rules in a real browser, and a
production-shape build. It prints a summary and ends with `VERIFY: PASS` or
`VERIFY: FAIL`; logs and screenshots go to `.evidence/<MILESTONE>/`.

```sh
MILESTONE=check ROUTES="/,/about/" scripts/verify.sh
SHOW_SAMPLES=0 scripts/verify.sh     # what a public build contains
```

The colour audit step needs the sibling `wit-et-design-system` checkout and is
skipped when it is absent.

## Share cards

`npm run og` draws a 1200x630 card for every published post and a default one
into `public/og/` (git-ignored) using Playwright with Chrome. It runs before
every build. If it fails, it only warns and pages use the default card.

## Deployment

Pushing to `main` runs `.github/workflows/deploy.yml`: `npm ci`, `npm run
build`, then the `dist/` folder is published with GitHub Pages. The site is a
user site served from the root, so no `base` is set; `SITE_URL` overrides the
site address for other hosts. Pull requests run `.github/workflows/ci.yml`
(type check, build, link and colour checks, type rules).

GitHub Pages must be set to deploy from GitHub Actions in the repository
settings once before the first deploy.

## Sample posts

A post with `sample: true` exists only to exercise the layouts. It is shown in
`npm run dev` and in builds with `SHOW_SAMPLES=1`, never in a production build:
not in the lists, the sitemap, the feed, or the output folder. The deploy
workflow does not set that variable.
