# E-1.3 — Article reading pages (part 1: ESSAY / BUILD / PHOTO+TRAVEL)

## What

Adds `/posts/<slug>/` for all 11 seed posts, dispatched by `tag` (via
`src/lib/modes.ts`'s `modeForTag`, never hardcoded in a page) to one of
three layouts built from `design-ref/wit.et Blog.dc.html`:

- `src/layouts/EssayLayout.astro` — ESSAY (`1e`), paper mode, vendored
  `src/styles/vendor/article.css` (`wit-et-design-system` @
  `feat/e4-article-layout`, pulled by `scripts/sync-tokens.sh
  feat/e4-article-layout`) for the long-form prose idiom.
- `src/layouts/BuildLayout.astro` — BUILD (`1f`/mobile `1h`), deep-space
  mode, 200px sticky TOC on desktop / `<details>` disclosure on mobile
  (no JS either way), code blocks break out 110px past the content column
  on wide desktop and go edge-to-edge on mobile.
- `src/layouts/PhotoLayout.astro` — PHOTO and TRAVEL share this (`1g`),
  deep-space mode, 820px-capped title block, full-width cover image
  (`ImageSlot` placeholder when the post has no `cover`), 620px-capped body
  text.

New: `src/styles/prose-deep.css` (the deep-space counterpart to
`article.css`, mirroring its class names per the brief), `src/lib/markdown-
plugins.mjs` (`rehypeFigureImages` turns a standalone markdown image into a
`<figure>`/`<figcaption>`; `rehypeCodeBar`, scoped to `tag: build`, wraps
each code fence in a language bar). `astro.config.mjs` now pins
`markdown.processor` to `unified()` (see "Astro version note" below) and
turns off syntax highlighting.

Reused as specified: `SiteHeader` (`glow={false}`, extended with a `nav`
prop for the "索引 / 關於 / RSS" article nav vs. the homepage's "關於 /
Projects / RSS"), `ImageSlot` (PHOTO's cover placeholder). `Base.astro`
gained a `noindex` prop (all 11 seed posts carry `sample: true`, so all 11
pages render `<meta name="robots" content="noindex">`).

**Not in this ticket** (per the brief): tag pages, RSS feed — see
"Part 2" below.

## Why

The homepage's (E-1.2) cards all link to `/posts/<slug>/`, which 404s
today. This closes that gap so a morning read-through actually works.
`docs/DECISIONS.md` C1/C2/C3 govern the mode-per-tag map, the font-scale
override, and the alpha-color convention — all three are exercised here
for the first time (E-1.2 was deep-space-only and had no vendored prose
CSS to collide with).

```bash
MILESTONE=e1-3a ROUTES="/posts/why-programmers-should-write-essays/,/posts/git-worktree-no-more-stash/,/posts/kaohsiung-harbor-cargo-ship-3am/" scripts/verify.sh
# last line: VERIFY: PASS
```

Note the comma separator — `scripts/verify.sh` splits `ROUTES` on `,`, not
spaces.

```bash
npm run build && ls dist/posts/*/index.html | wc -l   # 11
```

Manual spot-check at 375/768/1280: no horizontal scrollbar on any of the
11 `/posts/<slug>/` pages; ESSAY pages show a bordered `essay` tag + date +
minutes, the ESSAY footer links to the previous *essay* by date (two of
the three essays have one; the oldest, `rewriting-personal-site-fourth-
time`, correctly has no footer); BUILD's TOC lists only `h2`s and is
`position: sticky` at ≥768px, and collapses into a `<details>` above the
content at <768px; BUILD code blocks show a `bash` bar and extend right of
the body text at 1280px; PHOTO/TRAVEL pages show `date · location · N
FRAMES` (each part only when the post's frontmatter has it).

## Deliberate differences, judgment calls, and [TBD]s

- **Astro version note**: this repo's Astro (7.3.5) defaults to a new
  native "Sätteri" Markdown processor whose plugin API isn't
  rehype/unified-compatible; `markdown.rehypePlugins` is deprecated under
  it and `astro check` refuses to run until a processor is picked
  explicitly. Rather than port `rehypeCodeBar`/`rehypeFigureImages` to
  Sätteri's visitor API, `@astrojs/markdown-remark` was added as a
  dependency and `markdown.processor` set to its `unified()` export, which
  keeps the standard rehype plugin shape. `markdown.syntaxHighlight: false`
  (not deprecated) stays at the top level either way.
- **MonoTag not reused for article meta rows**: the brief lists `MonoTag`
  among the components to reuse, but it has no border box and isn't
  mode-aware (always `--moss-300`), so it can't reproduce 1e/1f/1g's
  bordered tag + mode-tinted meta text. All three layouts use
  `article.css`'s own `.wt-tag`/`.wt-meta-row`/`.wt-meta` classes instead
  (mirrored in `prose-deep.css` for deep-space). `SiteHeader` and
  `ImageSlot` are reused as specified.
- **BUILD's "TIL" meta suffix**: `1f`'s example card reads "2 MIN · TIL" —
  read as a one-off label on that specific mock post (its title also
  starts with "TIL："), not a schema field (no `til` in
  `src/content.config.ts`). Not rendered on any post; no data source for
  it exists today.
- **Code bar language label**: shows the fence's actual language token
  (`bash` for both blocks in `git-worktree-no-more-stash.md`), not the
  per-block file names (`bash` / `.zshrc`) `1f`'s mock uses — markdown
  fences don't carry a filename, only a language.
- **Code breakout only guaranteed at ≥1150px**: the -110px breakout is
  gated behind `@media (min-width: 1150px)` in `BuildLayout.astro`. Below
  that (down to the 768px mobile breakpoint), the code block sits flush
  with the body text instead of overflowing — at 768px, 72px container
  padding + 200px TOC + 56px gap only leaves room for a content column
  well under 640px, so a further 110px breakout would push the page wider
  than the viewport. The brief only specifies the 1280px case.
- **Grid track `minmax(0, …)` fix**: `BuildLayout`'s grid columns use
  `minmax(0, 200px)` / `minmax(0, 1fr)` rather than bare `200px`/`1fr`. A
  `<pre>` with unwrapped long lines otherwise sets the implicit `auto`
  minimum of its grid track to its max-content width, overflowing the
  viewport even through the `pre`'s own `overflow: auto` — caught via
  `scripts/shoot.mjs`'s overflow check on `git-worktree-no-more-stash.md`
  at 375/768px before this fix (70px and 7px overflow respectively; 0px
  after).
- **TOC "current position" highlight**: `1f` shows one TOC item in the
  accent gold token with a highlighted left rule, tracking scroll
  position. Needs client JS; out of scope tonight per the brief. Every TOC
  item renders uniformly in `--moss-300` instead.
- **Code block "copy" button**: omitted — an inert label would mislead, and
  clipboard support needs client JS. `[TBD]`.
- **PHOTO/TRAVEL multi-image grid**: `1g`'s mock shows a 2-up image grid
  below the hero photo. Markdown doesn't encode "these two images are a
  pair," so `rehypeFigureImages` renders every standalone markdown image
  as its own full-width `<figure>` instead — unexercised by any of the 11
  seed posts (none have body images or a `cover`). `[TBD]` if a paired
  layout is wanted later.
- **ESSAY lede renders at 18px, not 19px**: the brief names
  `site-scale.css`'s `--article-body`/`--article-measure`/`--article-
  caption` block as the one allowed override point; `1e`'s lede is 1px
  larger (19px) than its body text (18px) in the mock. Not given its own
  override var to keep to that single point — it inherits `--article-
  body`.
- **`html body[data-mode="paper"] .wt-article` selector** (in
  `site-scale.css`, not the bare `[data-mode="paper"] .wt-article` the
  brief's example shows): needed to reliably outrank `article.css`'s own
  identical-specificity selector regardless of Vite's CSS bundling order
  across the `EssayLayout` → `Base` import graph — without it, the override
  silently lost the cascade in testing (16px/36em, not 18px/620px).
