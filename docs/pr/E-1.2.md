# E-1.2 — Landing page

## What

Replaces the E-1.1 placeholder index with the real homepage, built from
`design-ref/wit.et Blog.dc.html` artboards `1a` (header + hero + filter bar)
and `1c` ("main direction" two-column index). `1b`/`1d` are rejected
alternatives and are not implemented.

New components under `src/components/`: `SiteHeader`, `Hero`, `FilterBar`,
`PostCard`, `BuildLog`, `ImageSlot`, `MonoTag`. `src/styles/site-scale.css`
holds the font-size overrides named in `docs/DECISIONS.md` C2. `global.css`
gained the named alpha-color variables required by C3 and a shared
`.container`/hover/focus-visible baseline.

## Why

This page is reused directly by E-1.3 (article pages pick up `SiteHeader`,
`MonoTag`, `ImageSlot` as-is), so the component boundaries matter more than
the page itself. Mode follows content per C1 — this whole page is
deep-space, single mode throughout.

## How to test

```bash
MILESTONE=e1-2 ROUTES=/ scripts/verify.sh   # last line: VERIFY: PASS
npm run preview                              # http://localhost:4321/
```

Manual spot-check: visit `/`, resize to 375/768/1280 — no horizontal
scrollbar at any width; the 5 filter items and "11 posts" count read
correctly; the first card (the newest post, a photo) sits above the fold at
1280px; clicking any card or a BUILD LOG row goes to `/posts/<slug>/`,
which 404s today (expected — E-1.3 builds those pages).

## Deliberate differences from the design ref

- **BUILD LOG total count**: the design mock shows a header count of "6"
  (line 233) while listing 5 items below it. This repo's actual seed
  content has exactly 5 `build`-tagged posts, not 6. The component computes
  the total from real content (`posts.length`), so it correctly shows **5**,
  not the mock's placeholder "6". Flagging this because it does not match a
  literal reading of this milestone's acceptance checklist, which expected
  "total 顯示 6" — that number appears to have been copied from the design
  mock's fictional sample data rather than recomputed against this repo's
  11 real seed posts (3 essay, 5 build, 2 photo, 1 travel).
- **Mobile hero size**: design-ref's mobile reference (`1h`) follows `1c`'s
  sibling `1b` rhythm, which has no hero section at all — `1b`/`1h` go
  straight from header to filter bar. Rather than drop the "wit, et
  cetera." hero on mobile (a bigger structural change with no artboard to
  check it against), it's kept and scaled down to `--fs-hero-mobile: 40px`.
  `[TBD]`: confirm with the user whether the hero should actually disappear
  below 768px.
- **384px / 300px fixed columns from 1c**: both are `minmax()`-clamped
  (`minmax(240px, 384px)` for the BUILD LOG column, `minmax(160px, 300px)`
  for the media-card image column) instead of literal fixed widths. At
  1280px they render pixel-identical to the mock; below roughly 900px they
  shrink instead of forcing horizontal overflow, which is what let the
  768px screenshot pass the zero-overflow gate.
- **Load more button**: not implemented, `[TBD]` per the brief.
- **SiteHeader `glow` prop**: added beyond the brief's stated `mode` prop,
  defaulting to `true` (today's homepage always shows the glow ring). This
  exists so E-1.3 can pass `glow={false}` to match the smaller, ring-less
  logo on `1e`/`1c`-style inner-page headers without forking the component.
