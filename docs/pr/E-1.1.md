# E-1.1 — Astro scaffold

## What

Sets up the Astro project skeleton for wit.et's personal blog:

- Astro (static output), TypeScript strict, no UI framework integration.
- `scripts/sync-tokens.sh [ref]` — pulls `tokens.css` (and `article.css`,
  when it exists) plus the logo SVGs from `wit-et-design-system` at a given
  git ref (default `master`) into `src/styles/vendor/` and `public/`.
  Idempotent; stamps each vendor file with its source ref + commit hash.
- `src/layouts/Base.astro` — shared `<html>`/`<head>`/`<body>` shell: sets
  `lang="zh-Hant"`, `data-mode` on `<body>`, loads vendor tokens + global
  CSS + the Google Fonts the brief specifies, with `preconnect`.
- `src/styles/global.css` — minimal reset. Defines `--font-stack` as
  `"Space Grotesk", var(--font-zh)` (not `var(--font-en), var(--font-zh)` —
  `--font-en` ends in a generic `sans-serif` fallback, which would always
  win over `--font-zh` for CJK text before it ever got a chance).
- `src/lib/modes.ts` — the one map from post tag to visual mode
  (`essay` → paper, `build`/`photo`/`travel` → deep-space), per
  `docs/DECISIONS.md` C1.
- `src/content.config.ts` — the `posts` content collection (glob loader over
  `src/content/posts/*.md`) with the agreed frontmatter schema.
- 11 seed posts under `src/content/posts/`, all `sample: true`. A few
  (worktree TIL, the two essays with quoted summaries, the photo/travel ones
  with quoted captions) carry real copy lifted from the design draft; the
  rest are short placeholders that extend their summary, clearly not
  pretending to be the author's real writing.
- `src/pages/index.astro` — a plain, undesigned list of all posts sorted by
  date, deep-space mode. Proves the collection renders; E-1.2 replaces it
  entirely.
- `scripts/verify.sh` — the one script later milestones and the verifier
  agent run: `astro check`, `astro build`, the design system's
  `color_audit.py` against a concatenation of all built HTML+CSS, a raw
  hex/`rgba()` grep over `src/` (excluding vendor and content), and
  Playwright screenshots of each route at 375/768/1280px checking for zero
  horizontal overflow. Prints one `VERIFY: PASS` / `VERIFY: FAIL (...)` line.

## Why

This is the foundation the next two milestones (E-1.2 landing page, E-1.3
article system) build directly on top of tonight, each picked up by a
different agent. Getting the layout, token sync, content schema, and
verification script right now — and documented — means those agents don't
have to re-derive any of it, and have one script to prove their own work
didn't break what's already here.

## How to test

```bash
npm install
npm run check          # astro check — 0 errors
npm run build           # astro build — static output to dist/
MILESTONE=e1-1 scripts/verify.sh   # full gate; last line should read VERIFY: PASS
```

Manual spot-check:

```bash
npm run preview          # http://localhost:4321
# visit / — a plain list of 11 posts, newest first, deep-space background
```

Re-sync tokens from the design system at any time (idempotent — running it
twice back to back produces no diff):

```bash
scripts/sync-tokens.sh master
git status --short   # should be empty on a second run
```
